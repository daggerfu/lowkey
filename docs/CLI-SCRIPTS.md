# lowkeyctl: пишем скрипты автоматизации

`lowkeyctl` — это не просто набор команд, а текстовый интерфейс с кодами выхода:
всё, что умеет lowkey с открытым окном сайта, можно собрать в bash-скрипт,
cron-задачу, Alfred workflow или Ting-шаг. Этот туториал учит писать такие
скрипты надёжно.

---

## 1. Установка и вызов

Хелпер живёт внутри приложения:

```sh
ctl=/Applications/lowkey.app/Contents/Helpers/lowkeyctl
"$ctl" HA status
```

Чтобы не писать путь каждый раз, один раз создайте ссылку в `~/bin`
(без sudo, см. [справку](https://bobuk.io/apps/lowkey/lowkeyctl/)):

```sh
mkdir -p ~/bin
ln -sf /Applications/lowkey.app/Contents/Helpers/lowkeyctl ~/bin/lowkeyctl
# ~/bin должен быть в PATH
```

Проверка: `lowkeyctl --help` печатает синтаксис.

**Коды выхода:** `0` — успех; `64` — ошибка в аргументах; ненулевое — команда
не выполнена (нет окна, метка не найдена, несколько совпадений, disabled и т.д.).

---

## 2. Философия: lowkeyctl — не Playwright

- Нет JavaScript, нет CSS/XPath-селекторов — только **точные метки** кнопок,
  полей и списков (видимый текст или `aria-label`).
- Нет чтения содержимого страницы: `inspect` возвращает только тип, метки и
  состояние контролов, не значения и не текст.
- Всё работает в пределах **origin стартового URL** сайта, в главном документе
  и открытых shadow roots (не в iframe).
- Сайт уже залогинен: профиль окна хранит сессию, аутентификацией в скрипте
  заниматься не нужно.

Поэтому сценарий скрипта: *открыть окно → дождаться контрола → нажать /
заполнить / прикрепить / сохранить PDF*, а не «распарсить страницу».

---

## 3. Окно: open, toggle, hide, rewind

```sh
lowkeyctl HA open      # создать или поднять окно (запустит приложение)
lowkeyctl HA toggle    # показать/скрыть
lowkeyctl HA hide      # скрыть, если запущено
lowkeyctl HA rewind    # показать и вернуться к стартовому URL
```

`open` и `toggle` сами запускают lowkey, если он не запущен — скрипт может
начинаться с них. `rewind` удобен как «сброс» перед сценарием: гарантированно
стартовая страница, а не случайное место в истории.

## 4. Разведка: status и inspect

Не кликайте вслепую — сначала смотрите, что есть на странице:

```sh
"$ctl" HA status --json
# {"alias":"HA","open":true,"visible":true,"minimized":false,"focused":true,"loading":false}

"$ctl" HA inspect --json
# [{"type":"button","labels":["Refresh list"],"disabled":false,"visible":true}, …]
```

- `status` не поднимает окно — можно опрашивать фоновые окна.
- `inspect` требует открытое окно. Список контролов — источник точных меток
  для `wait`/`click`/`fill`/`select`.

Разведка перед автоматизацией:

```sh
"$ctl" HA status --json
"$ctl" HA inspect --json | grep -q '"Refresh list"' && echo "кнопка на месте"
```

## 5. Ожидание: wait

Страницы грузятся не мгновенно. Вместо `sleep 5` используйте `wait`:

```sh
lowkeyctl HA wait                      # DOM готов, 10 секунд по умолчанию
lowkeyctl HA wait 'Refresh list'       # + есть видимый активный контрол с меткой
lowkeyctl HA wait 'Refresh list' --timeout 30
```

Таймаут — 1…300 секунд. `wait` не ждёт сетевую тишину и не кликает; он ждёт
появления контрола. Если метка не появилась — ненулевой код выхода, и скрипт
честно падает в ветку ошибки.

Паттерн «открыть и дождаться»:

```sh
"$ctl" HA open
"$ctl" HA wait 'Submit' --timeout 30 || { echo "форма не загрузилась"; exit 1; }
```

## 6. Действия: click, fill, select

```sh
lowkeyctl HA click 'Refresh list'          # кнопка или ссылка по точной метке
lowkeyctl HA fill 'Comment' 'Hello'        # input/textarea (не парольные поля)
lowkeyctl HA select 'Period' 'This month'  # нативный список: опция по тексту
```

Правила матчинга:

- Метка — **точная**, регистрозависимая; пробелы нормализуются.
- 0 совпадений, несколько совпадений или disabled-контрол → ошибка, **клика нет**.
- `fill`/`select` шлют `input` и `change`, но **не отправляют форму** — если у
  сайта нет собственного обработчика, ничего не «сохранится».

Один клик — один вызов; цепочка действий — последовательные команды:

```sh
"$ctl" HA fill 'Comment' 'Отчёт за ноябрь'
"$ctl" HA select 'Period' 'This month'
"$ctl" HA click 'Save'
```

## 7. Файлы: upload

```sh
lowkeyctl HA upload ~/Documents/report.pdf
lowkeyctl HA upload scan.png --field 'Attachment'   # если input'ов несколько
```

- Один обычный файл, до 8 МиБ; передаются **имя и байты**, не локальный путь.
- Страница должна быть на origin сайта; по умолчанию требуется ровно один
  file input (скрытый — можно); `--field` выбирает по точной HTML/ARIA-метке.
- Заменяет текущий выбор, шлёт `input`/`change`, форму не сабмитит.

---

## 8. PDF: save-pdf

```sh
lowkeyctl HA save-pdf ~/Desktop/report.pdf
```

- Печатает **весь** документ в A4 с print-стилями, включая контент ниже вьюпорта.
- Не перезаписывает существующий файл; lazy-контент и виртуальные списки
  сам не догружает.
- Меню-аналоги: Save as PDF… в контекстном меню страницы, ⌘⇧S.

Удобный приём — уникальное имя по дате:

```sh
"$ctl" HA save-pdf "$HOME/Desktop/HA-$(date +%Y-%m-%d).pdf"
```

## 9. Полный пример: ежедневный отчёт

```sh
#!/bin/bash
# daily-report.sh — открыть HA, обновить данные, сохранить PDF
set -euo pipefail

ctl=/Applications/lowkey.app/Contents/Helpers/lowkeyctl
alias_=HA
out="$HOME/Desktop/HA-$(date +%Y-%m-%d).pdf"

"$ctl" "$alias_" rewind                              # 1. к стартовому URL
"$ctl" "$alias_" wait 'Refresh list' --timeout 30    # 2. ждём контрол
"$ctl" "$alias_" click 'Refresh list'                # 3. обновляем
"$ctl" "$alias_" wait 'Export' --timeout 60          # 4. ждём кнопку экспорта
"$ctl" "$alias_" save-pdf "$out"                     # 5. сохраняем PDF
"$ctl" "$alias_" hide                                # 6. прячем окно
echo "готово: $out"
```

`set -euo pipefail` здесь важен: любая ошибка `lowkeyctl` (окно не открылось,
метка не нашлась) останавливает скрипт вместо бессмысленных попыток дальше.

## 10. Обработка ошибок

- **Не ретраить клики.** «Клик отправлен» ≠ «сайт обработал». Если `click`
  вернул ошибку — ветка ошибок; если вернул 0 — действие диспетчеризовано.
- Проверяйте JSON через `--json` и `jq` для устойчивых условий:

```sh
if [ "$("$ctl" HA status --json | jq -r .loading)" = "true" ]; then
  echo "ещё грузится"; exit 1
fi
```

- Понятные сообщения об ошибках хелпер пишет в stderr — логируйте их:

```sh
if ! "$ctl" HA click 'Save' 2>>/tmp/lowkey.log; then
  echo "не удалось сохранить, см. /tmp/lowkey.log" >&2; exit 1
fi
```

## 11. Автозапуск по расписанию (cron)

```sh
crontab -e
# каждый будний день в 9:00
0 9 * * 1-5 /Users/you/scripts/daily-report.sh >> /tmp/lowkey-cron.log 2>&1
```

Под cron нет GUI-сессии пользователя в привычном виде, но lowkey — обычное
пользовательское приложение: запускайте из пользовательского crontab, окна
появятся у вошедшего пользователя. `open`/`toggle` в скрипте сами поднимут
приложение.

## 12. Ограничения, о которых стоит помнить

- В Ubuntu-сборке (см. [UBUNTU.md](UBUNTU.md)) команды страниц пока не
  реализованы: `lowkeyctl` отвечает `unsupported on linux`; работают только
  команды окон и `status`.
- Метки меняются вместе с сайтом: после редизайна страницы скрипт «ломается» —
  лечится повторной разведкой через `inspect`.
- Не работает с iframe и чужими origin (включая кросс-доменные попапы).
- Один запуск — одно действие; параллельности нет, очередь команд — ваш скрипт.
- Для внешнего запуска сценариев есть альтернативы: диплинки `lowkey://HA/open`
  и т.п. (только навигация по окнам) и Ting `lowkey`-step — выбирайте их,
  когда не нужны клики и поля.
